# Declared breaking changes for docs/catalog/openapi.yaml.
#
# oasdiff --err-ignore matches by SUBSTRING: an entry suppresses a breaking
# change when the entry line CONTAINS oasdiff's own error text verbatim
# ("in API <METHOD> <path> <description>"), so prose may surround an entry but
# never interrupt it. Lines that match nothing — this header included — are
# inert. Removing an entry re-arms the gate for that change.
#
# Wave 181 (2026-08-06) retired every human-asserted operation from the catalog
# S2S face. Each removal below has a live twin on the user-token plane
# (/api/v1/user/catalog), where the actor is the bearer token instead of a uid
# a caller states about someone else. A cross-repo sweep found no external
# caller of any of them. Rationale and the per-op successors: docs/catalog/01.

in API GET /api/v1/catalog/edit/proposals/{id} api path removed without deprecation
in API POST /api/v1/catalog/edit/proposals/{id}/amendments api path removed without deprecation
in API POST /api/v1/catalog/edit/proposals/{id}/merge api path removed without deprecation
in API POST /api/v1/catalog/edit/proposals/{id}/decline api path removed without deprecation
in API POST /api/v1/catalog/edit/revert api path removed without deprecation
in API GET /api/v1/catalog/edit/snapshot api path removed without deprecation
in API PUT /api/v1/catalog/works/{workID}/covers/{coverID}/vote api path removed without deprecation
in API DELETE /api/v1/catalog/works/{workID}/covers/{coverID}/vote api path removed without deprecation

# Wave 185 (2026-08-07) closes the S2S WRITE plane. Wave 181 left create /
# withdraw / schema on the editing face and the two claim writes on the
# lifecycle face for backends that authenticate their own user; every removal
# below has a live twin on the user-token plane (createEditProposalUser,
# withdrawEditProposalUser, getEditSchemaUser, submitCatalogWorkUser,
# actOnCatalogClaimUser), where the actor is the bearer token rather than a uid
# a caller states about someone else. A cross-repo sweep at the sibling repos'
# origin refs and 48h of production access logs found zero callers of any of the
# five. The third-person READ plane deliberately survives — listEditProposals
# (proposer_uid names the person being looked at) and listCatalogClaimsByUser
# (forum's profile pages) are not affected. Rationale: docs/catalog/01 §4.2.

# The first entry says "api removed", not "api path removed": the PATH survives
# for the surviving GET (listEditProposals) and only the POST verb went, which
# oasdiff reports as a different rule.
in API POST /api/v1/catalog/edit/proposals api removed without deprecation
in API POST /api/v1/catalog/edit/proposals/{id}/withdraw api path removed without deprecation
in API GET /api/v1/catalog/edit/schema/{entity_type} api path removed without deprecation
in API POST /api/v1/catalog/works/submit api path removed without deprecation
in API POST /api/v1/catalog/works/{id}/claim-actions/{action} api path removed without deprecation

# Wave 194 (2026-08-08) removes the name{ja,zh,other} buckets from the S2S read
# face's NameHead / SiblingName / CharacterHead, replacing them with
# display_name + lang — the same retirement the public face takes in this wave,
# for the same reason: the buckets look like "this name in three languages" and
# are in fact one name filed under its own language, so an absent zh key reads
# as "no Chinese name" when it means nothing of the kind.
#
# Unlike the public face this needed no expand step first, because these shapes
# have ZERO live consumers. A sweep for callers of
# /api/v1/catalog/{names,characters}/{id}/works found only letmoe, which is not
# launched and is out of scope, and apps/web's generated catalog-api.ts, a
# whole-spec type dump no apps/web code calls. Ledger: refs/proj/193 §2.

in API GET /api/v1/catalog/characters/{id}/works removed the required property `data/character/name` from the response with the `200` status
in API GET /api/v1/catalog/names/{id}/works removed the required property `data/name/name` from the response with the `200` status
in API GET /api/v1/catalog/names/{id}/works removed the required property `data/name/siblings/items/name` from the response with the `200` status

# Wave 195 (2026-08-08) retires the org entity type. catalog_org and
# catalog_label.org_id are dropped; entity type 2 stays permanently
# unallocated. The table never held a row in any database and no label ever
# carried an org_id, so `entities.orgs` on the admin dashboard has published
# the constant 0 for its entire life — this removes a field, not a fact. The
# question it modelled ("which company is this brand under") is answered by
# catalog_label_relation, whose eight-relation graph a single nullable FK
# cannot express. Rationale: docs/catalog/01 §1.

in API GET /api/v1/catalog/stats removed the required property `data/entities/orgs` from the response with the `200` status
